# OntoZ 新 Agent 首页开发规范（Codex 必读）


> 状态：历史参考；与新版指南冲突时以新版指南为准
> 适用范围：OntoZ 新增 Agent 的首页／工作台首屏  
> 基准日期：2026-09-11  
> 参考实现：Zoe、Lily、Wendy Agent V2

本文是新增 Agent 开发前的执行规范。它将 `audit/agent-unification-20260910/proposal.md` 的设计结论与现有 Agent V2 实现收敛为一份开发契约。发生冲突时，按以下优先级处理：

1. 用户在当前任务中的明确要求；
2. 根目录 `AGENTS.md`；
3. 本文；
4. `audit/agent-unification-20260910/proposal.md` 的历史分析与审计记录。

## 1. 开发目标

新 Agent 必须复用统一的信息架构、布局、协作体验、视觉尺度和响应式行为，同时保留自身业务指标、运行流程、决策类型与操作逻辑。

统一的是“页面骨架和交互契约”，不是把所有 Agent 做成相同内容：

- 统一：页面标题区、右上状态模块、主工作区、协作区、输入框、断点、基础视觉、可访问性与验收方式。
- 可变：Agent 名称和定位、标题文案、业务指标数量、运行视图、最近动态、协作卡片类型、按钮文案与业务事件。
- 不允许：复制现有 Agent 后继续维护一套独立布局、另建一份共享样式副本、为了视觉统一改变既有业务状态或提交逻辑。

## 2. 源码与改动边界

项目根目录是唯一源码目录。正式改动只写入：

- `index.html`：页面结构和内容；
- `css/`：样式；
- `js/`：交互与状态；
- `assets/`：图片和图标。

不得把 Site 镜像、预览目录、构建目录或临时导出目录作为最终源码；不得创建 `index-copy.html`、`style-final.css`、`app-new.js` 等副本。发现 Site 与项目源码不一致时，以项目源码为准。

新 Agent 首页应优先接入以下现有共享实现：

| 文件 | 职责 | 新 Agent 的动作 |
| --- | --- | --- |
| `css/base.css` | OntoZ 颜色和语义变量 | 复用 `--oz-*`，不另建同义色值 |
| `css/agent-shared.css` | Agent V2 页面骨架、组件和响应式样式 | 扩展根选择器和业务选择器，不复制整份规则 |
| `js/agent-home-layout.js` | 内容宽度判断、协作弹层、待办入口、流程展开和动效控制 | 以配置化方式接入，不复制 IIFE 或重写一套监听器 |
| `index.html` | 当前 Agent 首页 DOM 与脚本引用 | 按本文结构契约新增页面 |

如果新 Agent 的需求超出共享能力，先扩展公共能力，再接入业务页面。共享扩展必须继续限定在 Agent 首页作用域，不能连带修改关联业务页或已有弹窗。

## 3. 页面结构契约

### 3.1 必需信息架构

桌面端采用两行两列的统一骨架：

| 位置 | 必需内容 |
| --- | --- |
| 顶部左侧 | Agent 身份、价值标题、一句说明、一个主操作和可选次操作 |
| 顶部右侧 | 运行状态、当前任务摘要、业务管理入口 |
| 主体左侧 | 数据概览、当前任务／运行视图、最近动态或执行摘要 |
| 主体右侧 | “与 Agent 协作”标题、待处理数量、决策／审核卡片、需求输入框 |

顶部状态区与下方协作区必须共用同一列线。标题和副标题允许自然换行，不以缩小字号或裁切换取单行。

### 3.2 必需 DOM 类名

新 Agent 根节点必须同时具有独立 ID、`.agent-v2` 和 `data-agent`：

```html
<section class="agent-v2" id="novaHome" data-agent="Nova">
  <header class="av2-header">...</header>
  <div class="av2-columns">
    <main class="av2-main">...</main>
    <aside class="av2-collab" aria-labelledby="nova-collab-title">...</aside>
  </div>
</section>
```

共享结构类的职责如下：

| 类名／属性 | 作用 | 要求 |
| --- | --- | --- |
| `.agent-v2` | Agent 首页作用域 | 必须有唯一根 ID 和 `data-agent` |
| `.av2-header` | 顶部两列 | 第一子项为标题区，第二子项为状态／管理模块 |
| `.av2-page-actions` | 标题下页面级操作 | 只放页面级主次操作，不放卡片内动作 |
| `[data-av2-compose]` | 打开协作区并聚焦输入 | 页面主操作需要进入协作时使用 |
| `.av2-columns` | 主体两列 | 只包含主工作区和协作区 |
| `.av2-main` | 主工作区 | 指标、运行视图、动态按业务优先级纵向排列 |
| `.av2-collab` | 唯一协作面板 | 桌面常驻；窄屏由脚本移动到原生 `dialog` |
| `[data-av2-close]` | 关闭窄屏协作区 | 必须有清楚的无障碍名称 |
| `.av2-prompt-box` | 统一输入框 | 保留业务自己的 `form`、输入 ID、提交逻辑和状态反馈 |
| `.av2-flow-toggle` | 小屏展开／收起完整流程 | 只在小屏展示，不属于运行视图 Header |

不要预先在 HTML 中复制协作面板或创建第二套移动端表单。`js/agent-home-layout.js` 必须移动同一个 `.av2-collab`，以保留输入内容、卡片状态、事件处理器和滚动位置。

### 3.3 业务接入配置

将新 Agent 加入 `js/agent-home-layout.js` 时，至少配置：

- 根节点选择器；
- 待处理数量的数据源；
- 运行视图容器；
- 关联业务弹窗（如有）；
- 从业务弹窗返回时需要恢复的滚动容器；
- 小屏折叠时保留／隐藏的运行步骤。

不得仅把新根 ID追加到查询选择器而忽略数量源、弹窗恢复和小屏流程。优先把当前按根 ID 分支的内容整理为配置对象，避免第四个 Agent 继续扩大条件表达式。

协作区打开时应派发 `agent:collaboration-open` 事件。业务代码可监听该事件刷新待办，但布局脚本不负责修改业务数据。

## 4. 响应式布局契约

断点以扣除导航和页面左右留白后的可用内容宽度 `C` 为准，不直接以设备屏幕宽度代替。

| 可用内容宽度 | 页面布局 | 协作区 | 页面留白 |
| --- | --- | --- | --- |
| `C >= 1040px` | 左侧自适应 + 右侧栏 | 常驻并 sticky，宽 360–520px | 通常 32px，较窄桌面 24px |
| `640px <= C < 1040px` | 单列主工作区 | 右侧原生模态抽屉，最大宽 480px | 24px |
| `C < 640px` | 单列且按处理优先级排列 | 全屏原生模态面板 | 16px |

右侧栏随内容区连续增长：

| `C` | 右栏目标宽度 |
| --- | --- |
| 1040–1279px | 360–400px |
| 1280–1599px | 400–450px |
| 1600–1920px | 450–520px |
| 超过 1920px | 内容区保持最大 1920px，右栏保持 520px |

实现要求：

- 桌面协作区高度按当前可用视口计算，最低 320px；Header 与输入区固定，只有对话流滚动。
- `C < 1040px` 时设置 `data-av2-compact="true"`，展示带待办数量的 `.av2-attention` 入口。
- `C < 640px` 时设置 `data-av2-small="true"`，标题 30/40px，指标优先每行两项，输入文字 16px。
- 手机运行视图改为“当前步骤 + 关键结果 + 步骤列表”，完整流程通过 `.av2-flow-toggle` 展开。
- 页面本身不得横向滚动；只有 Tabs、表格等局部容器可按需横向滚动。
- 软键盘与安全区不得遮挡输入框和提交按钮。

## 5. 统一视觉规格

### 5.1 基础尺度与颜色

| 项目 | 规格 |
| --- | --- |
| 页面背景 | `--oz-indigo-50` / `#EEF2FF` |
| 卡片和输入底色 | `--oz-card`、`--oz-white` / `#FFFFFF` |
| 正文 | `--oz-foreground` / `#0A0A0A` |
| 次级文字 | `--oz-muted-foreground` / `#737373` |
| 边框 | `--oz-border` / `#E5E5E5` |
| 品牌强调 | `--oz-indigo-500` / `#6366F1` |
| 模块内默认主按钮 | `--oz-primary` / `#171717`，文字 `--oz-primary-foreground` / `#FAFAFA` |
| 页面标题 | 宋体回退；桌面 48/56px，中屏 40/48px，手机 30/40px；700 |
| 正文／说明 | 14/22px；13/20px；辅助信息最低 12/18px |
| 模块／卡片标题 | 18/26px、600；16/24px、600 |
| 数据数字 | 桌面 32/40px，手机 28/36px，等宽数字 |
| 间距 | 4、8、12、16、20、24、32px |
| 圆角 | 主卡片 16px；内嵌卡片 12px；普通控件 10px |

主题色 `Indigo-500` 与语义 `primary` 不同。不要把品牌紫色直接覆盖为全局 `primary`，也不要把 Tailwind 默认 OKLCH 与项目审计后的 sRGB HEX 混用。

### 5.2 页面级主次操作

只作用于 `.av2-header .av2-page-actions`：

- 横向 Flex，gap 8px，允许换行；桌面标准高度 36px。
- 页面级主按钮：`padding: 8px 16px`、胶囊圆角、无边框、蓝紫径向渐变、白字、`0 1px 2px rgba(0,0,0,.1)`。
- 页面级次按钮：`padding: 7px 10px`、白底、1px 边框、深色文字、胶囊圆角。
- 图标 16px、描边 1px、图文间距 4px。
- 手机点击高度至少 44px。

页面级按钮的特殊渐变不能下沉为全局按钮样式，卡片和表单按钮仍使用语义 `primary`。

### 5.3 顶部右侧状态／管理模块

顶部右侧模块使用统一表面：

```css
padding: 16px 24px;
gap: 12px;
min-height: 76px;
border: 0;
border-radius: 12px;
background: var(--oz-black-4);
box-shadow: inset 0 2px 4px var(--oz-black-6);
```

内部图标容器为 36 × 36px、Indigo-50 背景、10px 圆角；图标 24px。主信息使用 16/24px、500–600；辅助信息使用 12/16–18px、400。内容允许自然增高，不为固定 76px 裁切状态或入口。

### 5.4 协作面板

协作面板外框保留 1px 边框、16px 圆角和弱阴影；内部作为一个连续界面：

- Header：`padding: 12px`，无底部分割线；
- Tabs／快捷操作：与面板左右边缘保持 12px，内部 gap 8px；
- 对话流／卡片列表：`padding: 12px`，是协作面板唯一纵向滚动区；
- 输入框外围：`padding: 12px`，无顶部分割线；
- Header、对话流和输入框之间不使用横向分割线。

决策卡片按“标题 → 依据 → 影响／预览 → 主次操作”排列。必须覆盖待处理、已处理、空、加载、错误和长内容状态。图片预览保持自然比例，不为卡片等高裁掉业务文案。

### 5.5 协作输入框

统一 `.av2-prompt-box`，宽度跟随侧栏，不写死 376px：

```css
box-sizing: border-box;
display: flex;
flex-direction: column;
align-items: flex-start;
gap: 12px;
width: 100%;
height: 96px;
min-height: 96px;
padding: 16px;
background: var(--oz-white);
border: 1px solid var(--oz-border);
border-radius: 16px;
```

输入行 14/20px、无独立边框和背景；placeholder 使用 `--oz-muted-foreground`。操作行高 32px、右对齐。提交按钮最小宽 68px、高 32px、padding 8px 10px、gap 4px、Indigo-50 背景、10px 圆角；文字和 16px 图标使用 Indigo-500。

聚焦时只在外容器显示 Indigo-500 边框和 3px/12% 焦点环。必须保留与输入控件关联的 `label`，placeholder 不能替代 label。禁用态使用 Neutral-100／400。手机输入文字为 16px，但输入框内提交按钮仍保持 32px 高。

### 5.6 运行视图容器

运行视图直接呈现业务内容，不显示独立 Header，也不显示“运行视图／Agent 运行视图”标题、状态说明或“暂停动效”开关。模块仍需通过 `aria-label="Agent 运行视图"` 保留可访问名称。

桌面端动效按当前业务节奏自动播放；页面不可见、系统开启 `prefers-reduced-motion` 或进入小屏模式时自动暂停。手机端保留 `.av2-flow-toggle`，用于展开或收起完整流程，但它不能被放进已移除的 Header。

## 6. 交互与可访问性

- 所有图标按钮必须有可访问名称；装饰图标设置 `aria-hidden="true"`。
- 抽屉使用原生 `dialog.showModal()`；支持 Esc、遮罩关闭、Tab 焦点循环和关闭后的焦点回收。
- 从协作区打开业务弹窗时，先让出顶层；业务弹窗关闭后恢复原卡片焦点和列表滚动位置。
- 待办入口用 `aria-controls` 关联 dialog，并同步 `aria-expanded`。
- 运行视图不显示播放／暂停控制；页面隐藏、小屏或系统开启 `prefers-reduced-motion` 时自动暂停。
- 点击目标在手机上通常至少 44px；统一输入框内的 32px 发送按钮是明确例外。
- 状态不能只靠颜色表达，必须同时有文字或图标语义。
- 正文不得缩至 12px 以下来容纳布局；流程节点也不得使用不可读的小字。

## 7. 推荐开发顺序

1. 阅读 `AGENTS.md`、本文、`css/base.css`、`css/agent-shared.css` 和 `js/agent-home-layout.js`。
2. 检查新 Agent 的路由、现有事件、表单提交、弹窗和数据源引用关系。
3. 在 `index.html` 按结构契约搭建唯一 DOM，先保留业务语义和原有交互。
4. 把根节点与业务特有选择器接入 `css/agent-shared.css`，只为独有运行视图补充作用域样式。
5. 以配置方式接入 `js/agent-home-layout.js`，验证待办数量、同一协作 DOM 移动、弹窗返回和动效控制。
6. 检查桌面、平板、手机和状态组合；修复后再考虑更新 Site 或部署。

## 8. 完成定义（DoD）

开发完成前必须逐项确认：

- [ ] 新 Agent 使用统一标题区、列线、卡片外观、字号和操作层级。
- [ ] 顶部右侧模块是半透明深色叠加底、内阴影、12px 圆角。
- [ ] 协作区 Header、对话流和输入框区域都是 12px 内边距且没有内部横向分割线。
- [ ] 协作输入框为 96px 高、16px 内边距、16px 圆角，提交按钮符合 32px 规格。
- [ ] 运行视图直接显示业务内容，不存在独立 Header 或暂停动效开关；模块具有可访问名称。
- [ ] 360、390、768、1024、1280、1440、1920、2560、3440px 及 640／1040px 断点两侧无横向溢出、裁切或遮挡。
- [ ] 导航展开／收起后仍按内容宽度响应，右栏连续增长至 520px。
- [ ] 窄屏通过待办入口打开同一个协作面板；输入、状态和滚动不会因跨断点丢失。
- [ ] 运行视图在手机端有可读的线性摘要，完整流程可展开。
- [ ] 待处理、已处理、空、加载、错误、长标题、大数字和多卡片状态均可用。
- [ ] 键盘焦点、Esc、焦点回收、减少动态效果和软键盘安全区通过检查。
- [ ] 浏览器控制台无新增错误；图片、字体和图标正常加载。
- [ ] 新 Agent 的原业务主路径、关联页面和弹窗未被公共样式误改。
- [ ] 所有正式修改只在项目源码，未直接修改 Site 镜像或创建重复源码。

## 9. 非本规范范围

本文默认只约束 Agent 首页。创建向导、详情页、列表页、编辑器、日历、数据看板和既有弹窗在单独检查后再接入同一基础尺度，不因新增首页自动重做。发布、部署和 Site 同步也不是新增 Agent 页面代码完成后的默认动作，必须按任务范围另行执行。

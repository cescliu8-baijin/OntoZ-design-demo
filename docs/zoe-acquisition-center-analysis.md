# Zoe 自主获客中心：POC 拆解与 OntoZ 复刻说明

## 1. POC 的产品目标

POC 将传统的“填写搜索条件并等待结果”改造成一个持续运行的自主获客工作台。用户关注结果、任务状态和需要自己判断的少量边界案例，搜索、过滤和策略调整由 Zoe 自动完成。

核心用户目标有三个：

1. 快速知道 Zoe 今天找到了多少公开结果和高质量线索。
2. 理解 Zoe 正在做什么，并能下钻查看关键执行依据。
3. 用很少的人工判断和配置，持续校准并启动新的获客任务。

## 2. POC 功能拆解

### 2.1 自主获客总览

- 展示“全网搜索发现”和“高质量线索”两类核心结果。
- 用四段业务链路解释 Zoe 的工作：买家开发策略、全网实时搜索、精准线索匹配、自主策略迭代。
- 结果数字、链路状态和任务阶段会持续更新，营造“系统正在工作”的明确反馈。

### 2.2 执行过程下钻

- 买家策略：展示客户方向、市场分配、正向判断和排除边界。
- 全网搜索：展示 LinkedIn、Google、X、Meta 等公开来源，以及搜索规划、解析归并和结果池。
- 精准匹配：展示去重、域名识别、市场过滤、业务匹配和角色验证等环节。
- 策略迭代：展示搜索资源、过滤边界和候选客户方向如何根据结果与人工反馈更新。

### 2.3 多任务进度

- 支持切换三个并行任务。
- 每个任务展示今日分析量、今日线索量、累计线索、运行时长和当前执行阶段。
- 七段任务阶段自动轮转，让用户能看到任务没有停滞。

### 2.4 人类监督

- 按买家方向切换待判断公司。
- 每家公司支持“目标客户 / 不是目标 / 不确定”三种判断。
- 完成判断后，同一位置自动补入下一家公司。
- 判断结果被表述为 Zoe 的学习输入，而不是阻塞任务的审批流程。

### 2.5 新建获客任务

- POC 将配置压缩为五个关键选择：业务方向、买家画像、优先市场、人工接手边界、发现后的动作。
- 每一步都提供 Zoe 推荐，避免用户从空白开始配置。
- 最后汇总策略并启动任务，结果进入客户池。

## 3. POC 技术架构

POC 是纯前端演示，不连接业务后端。

- `index.html`：总览、下钻弹层、任务进度和人工监督的结构。
- `styles.css`：暗色高科技视觉、响应式布局、弹层和动效。
- `app.js`：演示数据、双层 Canvas 网络、阶段轮转、计数增长、弹层、任务切换与人工监督。
- `create-task.html / create-task.css / create-task.js`：独立的新建任务流程。
- `server.mjs`：本地静态服务器。

状态主要保存在浏览器内存中，通过数组、索引、计时器和 DOM 更新驱动。Canvas 只负责网络和数据流的视觉表达，业务数据仍由 JavaScript 中的演示对象提供。

## 4. 在 OntoZ 中的功能映射

| POC 能力 | OntoZ 中的实现 |
| --- | --- |
| 两个核心结果数字 | 扩展为搜索发现、高质量线索、平均匹配率、待人工判断四个指标 |
| 四节点 Canvas 网络 | 改为可读、可操作的四阶段链路卡片，降低视觉噪音并适配现有产品 |
| 节点下钻大屏 | 改为右侧执行详情抽屉，保留来源、判断依据和执行路径 |
| 三个运行任务 | 保留任务切换、实时阶段、指标、运行时长和进度条 |
| 人类监督 | 保留三类买家方向、三种判断和自动补位 |
| 独立创建任务页 | 合并进 `#zoe` 页面，形成“总览 / 创建任务”两层体验 |
| 五项关键配置 | 保留 Zoe 推荐、可修改选项、实时任务预览和启动成功态 |

## 5. OntoZ 实现架构

### 页面结构

`index.html` 中的 `#zoePage` 负责两种页面状态：

- `data-zoe-screen="overview"`：自主获客总览。
- `data-zoe-screen="create"`：五步任务创建流程。

执行详情使用同页 `#zoeStageDialog` 抽屉，不新增路由，继续沿用当前项目的 hash 导航。

### 视觉系统

`css/zoe.css` 复用 OntoZ 的色彩变量、字体层级、白色卡片、浅灰画布、紫色主操作和现有侧栏。布局在桌面端使用工作台网格，在平板和手机端依次降为单列；手机端不产生横向滚动。

### 交互与状态

`js/zoe.js` 使用数据驱动方式组织：

- `stageData`：四个获客阶段及详情内容。
- `taskData / taskStages`：多任务数据和七段执行状态。
- `personaCompanies`：三类买家方向的人工判断队列。
- `createSteps`：五步任务配置及默认推荐。

交互状态集中在单一 `state` 对象中，包括当前阶段、当前任务、当前画像、待判断队列和任务创建选择。动态内容在渲染时进行转义，避免将文本直接拼接为不可信 HTML。

### 可访问性

- 阶段、任务和画像切换使用 `tablist / tab` 语义并支持方向键。
- 任务配置选项使用 `radiogroup / radio`。
- 执行详情使用模态对话框，支持 Esc 关闭、焦点回退和基础焦点循环。
- 动态区域使用 `aria-live`，并为 reduced-motion 用户移除脉冲动画和过渡。

## 6. 当前边界

本次实现仍是产品 Demo：

- 搜索结果、线索数量和公司信息均为演示数据。
- 全网搜索没有请求 LinkedIn、Google、X 或 Meta。
- 新建任务、人工判断和计数变化只保存在当前浏览器会话，没有后端持久化。
- 接入真实产品时，需要将 `stageData`、`taskData`、人工判断队列和任务创建动作替换为业务 API 与任务事件流。
